## Entra Credential Coverage — 1.0.0 (2026-11-27)
Find gaps and overlapping validity periods in a supplied list of Entra app credentials. Paste or open non-secret CSV metadata with exactly `AppId,Kind,CredentialId,StartUtc,EndUtc`; use application/client GUIDs, credential key-ID GUIDs and kind `secret` or `certificate`. Enter an explicit UTC review horizon, select Review coverage and download complete JSON or protected CSV. Application/kind groups stay separate; missing groups are not inferred. Half-open validity windows show gap, single and overlap minutes with supporting IDs. No sign-in, permissions, admin consent, API or additional license is required for this local calculation; metadata acquisition remains separately authorized.

Maximum 1000 rows / 1 MiB UTF-8, minute-aligned UTC timestamps in years 2000–2099, horizon up to 366 elapsed days. This custom CSV is not a raw Graph/portal export; seconds/offsets are rejected, not silently rounded. Metadata dates are not proof of working credentials, rollout, revocation, interchangeability or outage. Page-memory processing only; no upload/storage, and clear/reload cannot delete previous downloads. No tenant operations or rollback. Contract: `docs/credential-coverage.md`. Browser tests use `CREDENTIAL_TOOL_URL` and a fresh absolute `CREDENTIAL_EVIDENCE_DIR`.

## Mail DNS Cutover Worksheet — 1.0.0 (2026-11-24)
Prepare a multi-record DNS cutover handoff from planned timing and your TTL-lowering evidence. Enter one common cutover time with seconds and an explicit UTC/offset, then one row per MX/TXT/CNAME RRset: DNS name, old/new whole-second TTLs and optional actual lowering time. That time means the lower TTL was visible on all authoritative servers; this is entered evidence, not independently verified. Calculate planned lower-by deadlines, old-cache expiry, lead-time shortfalls and modeled window ends. Unknown lowering times stay unverified without asserted expiry/window. Explicitly download all-row JSON or protected review CSV. One to 100 RRsets, no values/priorities, no DNS lookup, configuration validation or tenant access. Detailed contract: `docs/mail-dns-cutover.md`.

No sign-in, permissions, admin consent, API or M365 license required. Page-memory processing only; no upload, persistence, analytics or runtime dependencies. Hosting sees ordinary static request metadata; exports include internal DNS names. Clear/reload does not erase original evidence/downloads or change DNS; no execution/rollback function. Model assumes TTL-honouring caches, not serve-stale, resolver floors, provider replication, SMTP retries or queued mail. Results do not guarantee propagation or establish migration completion/service-retirement timing. New browser suite uses `DNS_TOOL_URL` (default loopback port 3363), `DNS_EVIDENCE_ID` to name fresh outputs. Full four-tool local regression can share port 3363 by setting all four URL environment variables; run from an isolated receipt cwd with legacy nested receipt paths prepared.

No comprehensive name/reserved-name, file-size, destination content/existence, desktop sync, permission or migration-readiness assessment. Shortening a prefix does not resolve listed conflicts. Obtaining an authorized inventory remains separate.

## Local verification
Node.js 22+; no production package dependencies or build/transpilation. Serve the public folder on loopback:

```sh
python3 -m http.server 3359 --bind 127.0.0.1 --directory public
node --test tests/*.test.mjs
```

Browser tests require Playwright and Chromium installed separately. Set `PLAYWRIGHT_MODULE` to the installed module directory and `PLAYWRIGHT_EXECUTABLE` to your Chromium headless-shell binary. Defaults refer to the existing sibling dashboard installation on the build host. `TOOL_URL` overrides the review tool URL for HTTPS production smoke. Test manifests are synthetic, isolated from production. Tests include exact GUID validation, malformed/oversized input, secret-field exclusion, tuple deltas/duplicates, explicit downloads, file races, keyboard flow, desktop/mobile viewports and memory/network custody. Browser viewport checks are not physical-device or real-tenant checks.

## Release and rollback
Public static files are only `public/tools/`; source tests and this README are separate from served assets. No operating receipts, internal research, customer data or credentials are published. Freeze a SHA-256 manifest of public assets, tests, this documentation and the nginx candidate before independent review. Recheck it before commit and promotion. Serve only exact reviewed routes, not a directory catchall. Static release promotion uses an immutable directory plus atomic `tools-current` symlink; the dashboard's `current` link stays untouched. Preserve the previous tools link and nginx configuration outside nginx includes; on failure restore the previous link/configuration, validate nginx and reload.
