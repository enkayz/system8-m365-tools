SharePoint Path Budget

Compare SharePoint file-path lengths for two destination folders and download the results.

Local processing only · No sign-in, permissions or uploads · Files stay unchanged

Destination and file paths

Enter the literal decoded path after the hostname slash, without a leading or trailing slash. Include the site, library and any destination folders. No full URLs or queries. Prefix existence is not checked.

Use decoded names such as Shared Documents, not URL-encoded text. Percent sequences are counted literally: %20 is three characters, not a space. Nothing is URI-decoded, trimmed or repaired.

One file per line, with slash separators, for example Reports/Annual.xlsx. Include filenames, not folder-only entries. No absolute paths or backslashes. Plain text only; commas and quotes are literal, not CSV syntax. Empty lines are ignored and counted.

Maximum 1 MiB and 5,000 physical lines, including blank lines; a final line terminator is allowed.

Enter prefix A and a file-path list to begin.

Path-budget review

Budget status only — not migration readiness. Shortening a prefix does not fix within-list conflicts.

Exports always include every row, regardless of filter. Downloads contain internal paths; handle them as internal information. CSV prefixes formula-like cells with an apostrophe; JSON preserves exact values.

Counting rules and limits

Microsoft documents a maximum of 400 characters for the entire decoded file path including the filename. Destination prefixes are capped at 4,096 UTF-16 code units. Lists exceeding 50,000 related-line references are rejected without a partial report; reduce repetitions/conflicts and recheck the combined list. Splitting alone can hide cross-batch conflicts. This tool counts UTF-16 code units as a conservative planning convention, excluding the hostname and its following slash. Non-ASCII names are marked for manual review: non-BMP characters and Unicode case equivalence need destination validation. Matching uses ASCII case folding only; it is not a comprehensive Unicode collision check.

Exact duplicates, ASCII case-only full-path matches and a listed file used as a folder prefix are flagged with related source line numbers. Only conflicts within this list are checked. Existing destination content is not inspected.

No comprehensive invalid/reserved-name checks, file-size checks, desktop/Windows/macOS sync limits, permission checks, destination existence or migration-readiness assessment. A row within the budget is not a guarantee that SharePoint accepts it.

Permissions and data handling

No Microsoft 365 permissions, admin consent, tenant connection, API calls or additional license are required for this local tool. Obtaining an authorized file inventory is your responsibility.

Inputs and results remain in page memory. No uploads, analytics, browser storage or runtime dependencies are used. Static hosting receives ordinary page and asset request metadata. Opening external reference or source links contacts those sites.

Clear or reload discards this page's data, not your original files or previous downloads. Nothing is changed in SharePoint; there is no tenant operation to undo.
