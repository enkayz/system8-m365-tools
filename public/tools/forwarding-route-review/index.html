Exchange Forwarding Route Review

Trace routes and cycles in a supplied list of mailbox forwarding settings.

No sign-in, consent, license or API required. Input stays in this page’s memory; nothing is uploaded.

Supply normalized forwarding settings

Custom reshaped metadata, not a native Exchange export. Use exact columns Mailbox,ForwardTo, with one effective mailbox-level SMTP forwarding target per row. Blank ForwardTo means confirmed no forwarding in the supplied data.

1–500 unique mailboxes · 1 MiB UTF-8 · bare ASCII email addresses only. Addresses are lowercased after validation. Duplicate mailboxes, extra columns and blank rows are rejected.

Prepare the input and see an example

Resolve aliases to listed canonical mailbox addresses before using this tool. Normalize one effective mailbox-level SMTP target yourself; this tool does not interpret raw ForwardingAddress / ForwardingSmtpAddress precedence. Do not paste native report or PowerShell output without reshaping it.

Illustrative example — copy and replace, not a tenant fixture:

CSV quoting, BOM and CRLF are supported. No display names, SMTP: prefix, quoted email local parts, whitespace or non-ASCII addresses.

Route review

Supplied metadata only. A graph cycle is not proof that mail endlessly loops or is lost: Exchange loop prevention and policies affect delivery. An unlisted target is not necessarily external.

How to interpret routes

Listed stop: a listed mailbox has a blank target. Unlisted target: the final address has no supplied row. Cycle reached: a node repeats; the full route includes that closing repeat. Links counts each arrow, including the closing cycle link. Cycle members exclude upstream starters; cycle entry is the first repeated address encountered from this starter.

Every supplied mailbox gets a result. The view shows at most 100 matches; downloads always include every result, regardless of this filter.

Exports contain internal addresses. Handle them as internal metadata. CSV formula-like cells are prefixed with an apostrophe; JSON preserves normalized values.

Scope, data handling and limits

No live tenant or email access, privileged actions, security/readiness assessment or actual mail-loop verdict. No alias resolution, group expansion, inbox rules, transport rules, contacts, delivery-copy setting or forwarding-blocked checks.

No storage, analytics, runtime external dependencies or content network destinations. Static hosting receives ordinary page/asset request metadata. Clear or reload discards this page’s inputs and results, not your original files or previous downloads. No tenant changes occur, so there is no tenant rollback.

Reviews exceeding 50,000 total route entries are rejected in full, not truncated. Reducing scope may omit context; retain the original list for human review.
