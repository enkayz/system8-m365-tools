Microsoft 365 Change Window Review

Review a proposed tenant-admin change and its consecutive rollback allowance against each site’s local working schedule.

No sign-in, permissions, admin consent or additional Microsoft 365 license needed. Inputs stay in this page’s memory; no upload or storage.

Proposed window

Exact UTC format, minute precision; years 2000–2099. For example, 2026-11-26T10:00Z is 18:00 in Australia/Perth. Enter your proposed time; this example is not loaded.

Whole elapsed minutes, combined maximum 1440 (24 hours). Rollback follows execution immediately, not in parallel. Include execution checks in your estimate; the tool does not estimate duration or validate recovery.

For example: record a change reference or an assumption for the reviewer. Avoid secrets; downloads include these notes.

Site working schedules

Enter the sites affected by this proposed change, up to 20. The initial editable schedule is a default, not a customer record.

Exports include every reviewed site and the handoff notes. CSV prefixes formula-like cells for spreadsheet review; it is not an import file. JSON retains exact entered text. Handle downloads as internal.

Enter a UTC start, check the site schedules, then review local impact.

Local impact review

Counts are working-time collision minutes, not a risk score. No overlap is not approval or a staffing check.

Calculation, limits and data handling

Every elapsed minute in execution [start, execution end) and rollback [execution end, rollback end) is checked using its actual local date, weekday and time. Working hours include their start and exclude their end. Repeated daylight-saving minutes count twice when both occurrences fall in working hours; skipped local minutes do not occur.

This browser’s time zone rules are used, including daylight-saving transitions and date rollover. Browser versions can differ, and future time zone rules may change. Confirm the entered dates and local offsets with the affected sites before handing off.

No holidays, calendars or live service reads. One within-day interval per site; no overnight shifts or split shifts. Weekdays are local to each site. A zero rollback allowance means no rollback minutes were reviewed, not that rollback is unnecessary.

This is a local impact review only. It does not schedule Microsoft maintenance, estimate downtime, confirm authorization or approval, check staffing availability, validate a rollback plan, or read or change a tenant.

Bounds: 1–20 sites; names 1–80 characters; browser-supported IANA time zone identifiers up to 100 characters; at least one working weekday; HH:mm start before end; notes up to 1000 characters. Unsupported or excessive inputs block review rather than producing partial results.

No content network destinations, persistence, analytics, remote fonts or runtime dependencies. Static hosting receives ordinary page and asset request metadata. Clear or reload discards this page’s state, not original records or earlier downloads; no guaranteed memory erasure. Exports contain site names, schedules and notes: handle them as internal. There is no tenant action to roll back.
