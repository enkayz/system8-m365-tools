Model, limits and data handling

What the model calculates

  • Planned lower-by = cutover − old TTL.
  • Old-cache expiry = actual lowering time + old TTL.
  • Lead-time shortfall = max(0, old-cache expiry − cutover), in seconds.
  • Modeled window end = max(cutover + new TTL, old-cache expiry). Without an actual lowering time, neither expiry nor window end is asserted.

No DNS lookup or configuration validation is performed. Serve-stale, resolver TTL floors, provider replication, SMTP retries and queued mail are outside this model. No propagation guarantee or decommission recommendation is supplied.

Inputs and limits

1–100 RRsets, MX/TXT/CNAME only. ASCII DNS names up to 253 characters plus an optional final dot; labels up to 63 characters, letters, digits, hyphens and underscores, no edge hyphens. Use ASCII punycode for international names. Names are lowercased and a final dot is removed; duplicate name/type pairs are rejected. Record values, MX priorities and configuration correctness are not assessed.

TTLs: 0–2147483647 whole seconds; new TTL must not exceed old TTL. Dates: years 0001–9999, seconds required, up to three fractional digits, explicit Z or numeric offset. Lowering must not be after cutover. Each date input is limited to 35 characters.

Custody and permissions

No permissions, admin consent, API access or Microsoft 365 license is required. No authentication, upload, analytics or browser storage. Inputs and results stay in page memory until edited, cleared, reloaded or closed. No content network destinations; static hosting receives ordinary page and asset request metadata.
