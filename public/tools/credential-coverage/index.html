Entra Credential Coverage

Find gaps and overlapping validity periods in a supplied list of Entra app credentials.

No sign-in, permissions, admin consent or additional license needed for this local calculation. Metadata stays in this page’s memory; no upload or storage.

Credential metadata

Opening a file replaces the pasted metadata. UTF-8 CSV, maximum 1 MiB. It is read locally, not uploaded. Editing any input cancels a pending read.

Only these five columns, in this order: AppId, Kind, CredentialId, StartUtc, EndUtc. Use GUIDs and kind secret or certificate. Up to 1000 rows and 1 MiB UTF-8. Never paste secret values, tokens or private keys. Long CSV rows scroll sideways in the editor.

Review horizon

All times, including CSV dates, must use exact minute UTC: 2026-11-27T00:00Z. Years 2000–2099; start before end; horizon at most 366 elapsed days. No date-only, seconds or offset formats.

Supply metadata and a UTC horizon, then review coverage.

Tables show up to 100 rows each and up to 3 IDs per validity window; downloads include all groups, windows and supplied evidence. CSV protects formula-like cells for spreadsheet review, not import. Handle metadata downloads as internal.

Coverage review

Metadata validity only. A gap means no supplied credential of that application and kind covers that period. Overlap means 2+ distinct supplied credential IDs have intersecting validity dates; it is not a rotation or safety verdict.

Calculation, limits and data handling

Applications and credential kinds are reviewed separately. Certificates and secrets are not assumed interchangeable. Only application/kind groups present in the supplied rows are reviewed; missing applications, kinds and credentials are not inferred.

Validity intervals and the horizon include their start and exclude their end: [start, end). Adjacent boundaries are continuous, without an overlap. Intervals are clipped to the horizon. Fully outside rows remain in the evidence but do not provide coverage. Windows split whenever the active credential IDs change; overlap minutes count once, even with three or more credentials.

Exact GUID format is validated before lowercasing. Duplicate credential IDs within one application and kind block review. Header names and order are exact; extra fields, malformed rows, ambiguous dates and empty evidence block review. A UTF-8 BOM, quoted CSV fields and CRLF line endings are accepted. No credential values are required or accepted by the five-column schema.

This does not establish usable credentials, actual authentication, application rollout, interchangeability, revocation status or an outage. No live checks, tenant reads or tenant changes. Obtain metadata separately with appropriate authorization; this tool grants no access and does not check the completeness of your source.

No content network destinations, analytics, remote fonts or runtime dependencies. Static hosting receives ordinary page and asset request metadata. Clear or reload discards this page’s state, not original files or earlier downloads; no guaranteed memory erasure. There is no tenant operation to roll back.
